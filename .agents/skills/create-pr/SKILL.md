# PR 作成

1. `.github/pull_request_template.md` の現在の内容を読み、対象ブランチ・比較先ブランチ・差分・コミット・作業ツリーの状態を確認します。依頼に比較先の指定があればそれを優先します。
2. 差分から変更の目的と内容を把握し、テンプレートの「概要」「変更内容」を具体的に埋めます。要件・要求定義との紐付けは求めません。仕様 ID は、変更内容の説明に必要な場合だけ記載します。
3. 「テスト結果」には実行したコマンドと実際の結果を記載します。JUnit・Checkstyle の件数を推測で埋めません。未実施の項目は「未実施」と記載し、失敗した項目はその事実を記載します。
4. 対応する Issue が確認できる場合だけ `Closes #番号` を記載します。Issue がない、または番号を確認できない場合は、未完成の `Closes #` 行を残しません。
5. 内容が分かる簡潔なタイトルを付けます。PR 作成まで依頼されている場合は、差分がリモートに反映されていることと対象リポジトリを確認し、本文をファイルに保存して `gh pr create --title ... --body-file ...` などで起票します。コミットや push が必要な場合は、既存の依頼・許可の範囲を確認します。下書きだけの依頼なら起票しません。
6. 起票後は PR の URL、タイトル、比較先と対象ブランチ、テスト結果を報告します。起票できなかった場合は理由と作成済みの本文を伝えます。

テンプレートをこのスキルに複製せず、PR 作成時点の `.github/pull_request_template.md` を正とします。
