# 要件定義

## 1. 本書の目的

[要求定義](requirements.md) の要求を満たすための仕様を定義します。実装とテストは本書を根拠として行います。

## 2. 割り当て枠の導出

枠は要求定義の制約条件（C-1〜C-3）から一意に決まります。仕様変更時に前提を見失わないよう、導出過程を記録します。

1. **時間帯ごとの勤務中人数（C-3）**：営業時間 7:30〜18:30 の勤務中人数（休憩中の人を含みます）は次のとおりです

| 時間帯        | 勤務中人数 |
| ------------- | -------- |
| 7:30 〜 8:00  | 2 名     |
| 8:00 〜 8:30  | 3 名     |
| 8:30 〜 9:00  | 4 名     |
| 9:00 〜 14:30 | 8 名     |
| 14:30 〜 15:30 | 6 名    |
| 15:30 〜 16:30 | 5 名    |
| 16:30 〜 18:00 | 3 名    |
| 18:00 〜 18:30 | 2 名    |

2. **出勤と退勤の人数**：勤務中人数の増減から、出勤は 7:30 に 2 名・8:00 に 1 名・8:30 に 1 名・9:00 に 4 名（計 8 名）、退勤は 14:30 に 2 名・15:30 に 1 名・16:30 に 2 名・18:00 に 1 名・18:30 に 2 名（計 8 名）です
3. **出勤と退勤の対応（C-2）**：早く出勤した人から順に退勤します。9:00 出勤の 4 名は退勤時刻の早い順に 16:30・18:00・18:30・18:30 とします
4. **結論**：構成は次の一通りに定まります。1 日に勤務するのは 8 名です

| 枠（No） | 勤務時間       | 人数         |
| -------- | -------------- | ------------ |
| 1        | 7:30 〜 14:30  | 2 名（固定） |
| 2        | 8:00 〜 15:30  | 1 名（固定） |
| 3        | 8:30 〜 16:30  | 1 名（固定） |
| 4        | 9:00 〜 16:30  | 1 名（固定） |
| 5        | 9:00 〜 18:00  | 1 名（固定） |
| 6        | 9:00 〜 18:30  | 2 名（固定） |

従業員が 8 名を超える場合、割り当てられなかった従業員はその日の勤務なし（休み）として扱います。枠の名称（早番・遅番）は廃止し、「勤務時間」で表します。

従業員の雇用区分は「常勤」「パート」「管理職」の 3 択です。管理職は社長・部長などの役職者を指します。区分は入力・保存・表示だけを行い、割り当てには一切使いません。全従業員を区別せず同一に扱い、区分ごとの扱いは次の仕様変更で対応します（T-5 決定済み）。

### 休憩の割り当て（T-4 決定済み）

休憩は労働基準法第 34 条に従い、アプリが自動で割り当てます。勤務時間（休憩を含む拘束時間）に応じた休憩の長さは次のとおりです。

| 勤務時間           | 休憩の長さ |
| ------------------ | ---------- |
| 6 時間以下         | なし       |
| 6 時間超〜8 時間以下 | 45 分      |
| 8 時間超           | 60 分      |

各枠の休憩の長さは次のとおりです。

| 枠（No） | 勤務時間        | 拘束時間 | 休憩  |
| -------- | --------------- | -------- | ----- |
| 1        | 7:30 〜 14:30   | 7 時間   | 45 分 |
| 2        | 8:00 〜 15:30   | 7.5 時間 | 45 分 |
| 3        | 8:30 〜 16:30   | 8 時間   | 45 分 |
| 4        | 9:00 〜 16:30   | 7.5 時間 | 45 分 |
| 5        | 9:00 〜 18:00   | 9 時間   | 60 分 |
| 6        | 9:00 〜 18:30   | 9.5 時間 | 60 分 |

休憩の時刻は、次の規則で決定的に割り当てます。

1. 休憩は 12:00 以降に取り、同時に休憩できるのは 2 名までとします（2 章の勤務中人数は休憩中を含みます。休憩が始まる 12:00 以降は、休憩中の人を除いても 4 名以上が勤務しているため、常に 2 名以上を保ちます）
2. 割り当ては 12:00 から開始し、枠 1 → 6 の順、同じ枠の中では入力順に、1 人ずつ「休憩を開始できる最も早い時刻」を選びます。休憩は 1 分刻みでなく 15 分刻みの時刻から開始します
3. 休憩は自分の勤務時間内に収めます

この規則による割り当て結果は次のとおりです（同時休憩は 2 名まで）。

| 順 | 枠 | 休憩時刻        |
| -- | -- | --------------- |
| 1  | 1（1 人目） | 12:00〜12:45 |
| 2  | 1（2 人目） | 12:00〜12:45 |
| 3  | 2 | 12:45〜13:30 |
| 4  | 3 | 12:45〜13:30 |
| 5  | 4 | 13:30〜14:15 |
| 6  | 5 | 13:30〜14:30 |
| 7  | 6（1 人目） | 14:15〜15:15 |
| 8  | 6（2 人目） | 14:30〜15:30 |

休憩はどの割り当て案でも枠ごとに時刻が同じため、枠に入った人の休憩時刻はこの表のとおりです。

## 4. 入力仕様

### 4.1 入力項目

| 項目     | 必須 | 値                                                   |
| -------- | ---- | ---------------------------------------------------- |
| 対象月   | 必須 | 年月（例：2026 年 10 月）。日本の祝日データの範囲内の月を選びます（F-9、F-10） |
| 従業員名 | 必須 | 文字列。画面内で一意                                 |
| 雇用区分 | 必須 | 「常勤」「パート」「管理職」のプルダウンから選択します。既定は「常勤」です。割り当てには使いません |
| 基本シフト | 必須 | 曜日（月〜金）ごとに、「開始・終了」を設定します。既定は 7:30〜18:30 です。基本シフトには「休み」を設定できません（休みは個別変更で入力します） |
| 休み     | 任意 | 個別変更（画面 2）だけで入力できます。チェックするとその日は勤務しません（割り当て対象外）。既定は未チェックです |
| 開始・終了 | 基本シフトは必須。個別変更は休みでない場合は必須 | 勤務できる時間帯です。7:30〜18:30 の範囲で 30 分単位（例：`8:00`〜`17:00`、`9:00`〜`18:30`）のプルダウンから選択します |
| 個別変更 | 任意 | 営業日ごと・従業員ごとに、「休み」または「開始・終了」を基本シフトから変更します。基本シフトと同じ内容に戻したものは、変更なしとして扱います。従業員は氏名で指定します（F-11） |

従業員が入力するのは「勤務できる時間帯」です。従来の枠ごとの希望（◎／○／×）は廃止しました。

ある営業日のある従業員の希望は、次の優先順位で決まります。

1. 土曜日・日曜日・日本の祝日は営業しません。誰も割り当てず、入力も受け付けません
2. 営業日で、その日の個別変更があれば、個別変更の内容（休みまたは時間帯）を使います
3. 個別変更がなければ、その曜日の基本シフトを使います

祝日は内閣府の「国民の祝日」CSV（`https://www8.cao.go.jp/chosei/shukujitsu/syukujitsu.csv`。文字コードは Shift_JIS、1955 年から翌年までの祝日・休日を収録し、振替休日・国民の休日を含みます）を正規データとします。アプリは JDK 標準の HTTP クライアントで CSV を取得し、H2 に保存します。新しいライブラリは追加しません（T-9 決定済み）。取得はアプリの起動時と、対象年の祝日が保存済みのデータに含まれないときに行い、取得に失敗した場合は保存済みの祝日データを使います。保存済みのデータでも判定できない対象月は、V-8 のエラーとします。

### 4.2 入力チェック

| No  | 内容                                           | 挙動                                   |
| --- | ---------------------------------------------- | -------------------------------------- |
| V-1 | 従業員名が未入力の行                           | 処理対象から除外します（エラーとしません） |
| V-2 | 従業員名の重複                                 | 該当行を示してエラーメッセージを表示します |
| V-3 | 有効な行の基本シフト（曜日ごと）、および個別変更（「休み」でないもの）の開始・終了が未選択、選択肢以外の値、または開始が終了以上 | 該当する従業員・曜日（または日付）を示してエラーを表示し、算出しません |
| V-4 | ある営業日に、有効な従業員のうちその日「休み」でない人が 8 名未満 | エラーにせず、その日だけ算出せず不成立として扱います（他の日は算出します） |
| V-5 | 有効な従業員（休みを含む）が 13 名以上          | エラーメッセージを表示し、算出しません |
| V-6 | 従業員名が 255 文字を超える行                  | 行番号を示してエラーメッセージを表示し、算出も保存もしません |
| V-7 | 有効な従業員の雇用区分が「常勤」「パート」「管理職」以外 | 行番号を示してエラーメッセージを表示し、算出も保存もしません |
| V-8 | 対象月が年月の形式でない、または祝日データで判定できない月（保存済みの祝日データにも含まれない月） | エラーメッセージを表示し、算出も保存もしません |
| V-9 | 個別変更の日付が、対象月の営業日でない（土曜日・日曜日・祝日、または対象月以外の日付） | 該当する日付を示してエラーメッセージを表示し、算出も保存もしません |

「有効な従業員」は、従業員名が入力された行です。チェックはサーバー側で、V-1 → V-9 の順に行います。個別変更の従業員名が、有効な従業員のどの氏名とも一致しない場合は、その個別変更を無視します（エラーにしません。従業員の氏名の変更や削除に備えるためです）。

## 5. 割り当てルール

本章のルールは、対象月の営業日 1 日ごとに、独立して適用します。日をまたいだ調整（出勤回数の公平化など）は行いません（T-8 決定済み）。

### 5.1 ハード制約

すべて満たす組み合わせのみを案として扱います。

| ID  | 条件                                                          |
| --- | ------------------------------------------------------------- |
| H-1 | 枠 1 にちょうど 2 名、枠 2〜5 に各 1 名、枠 6 にちょうど 2 名を割り当てます |
| H-2 | 1 人が割り当てられる枠は、1 日に最大 1 つです                 |
| H-3 | 枠の勤務時間が、従業員の入力した時間帯に完全に含まれる場合だけ、その枠に割り当てます（枠の開始 ≧ 入力の開始、かつ 枠の終了 ≦ 入力の終了）。「休み」の従業員は割り当てません |

### 5.2 評価（ソフト制約）

> **スコア（ずれの合計）= 割り当てられた 8 名それぞれの「入力した時間帯の長さ − 割り当てられた枠の勤務時間」（分）の合計**

ずれが小さいほど、入力した時間帯を無駄なく使えている案です。**スコアが最小の案**を採用します（0 が最良です）。

例：8:00〜17:00（540 分）の人が枠 2（8:00〜15:30、450 分）に入ると、ずれは 90 分です。

### 5.3 同点時の決定方法

スコアが同じ案が複数ある場合は、次の順で列挙したときに **最初に最小スコアに到達する案** を採用します（同点では更新しません。列挙は採用する案を定義するための順序であり、5.4 節の探索方法もこの案を返します）。

1. 枠 1 → 枠 2 → … → 枠 6 の順に、枠ごとの人数分の組を、残りの従業員から入力順（従業員の並び順。全営業日で共通です）のインデックスの辞書順（枠 1 なら (0,1), (0,2), …）で選びます
2. 枠 1 の組ごとに、枠 2 以降を同じ規則で再帰的に列挙します

結果として、勤務開始が早い枠ほど、入力画面の上にいる人が優先されます。

### 5.4 探索方法

従業員の集合をビットマスクで表す動的計画法で、最小スコアの案を求めます。最適化ライブラリは使用しません（Issue #20 のレビューで、総当たりから変更。CPU 負荷を抑えるため）。

1. 状態は「次に割り当てる枠」と「割り当て済みの従業員の集合」です。各状態から先で得られる最小スコアを、メモ化して求めます。枠の勤務時間が入力時間帯に含まれない人を含む組と、「休み」の人を含む組は除外し、割り当てられない状態は「不可」とします
2. 案の復元は、枠 1 から順に、5.3 節の列挙順で組を調べ、「その組のスコア ＋ 次の状態の最小スコア ＝ 現在の状態の最小スコア」を満たす最初の組を選びます。これにより、5.3 節の「列挙順で最初に最小スコアに到達する案」と同じ案が得られます
3. 状態数は、従業員数を n、枠数を 6 として `6 × 2^n` 以下です（n = 12 で 2.5 万程度）。12 名でも数ミリ秒で終わります
- 従業員数の上限は 12 名です（V-5、T-6 決定済み）

## 6. 不成立時の仕様

不成立は営業日ごとに判定します。ハード制約を満たす案が 1 つもない日は、その日の案を出力せず、その日を不成立として表示します。他の営業日の結果は通常どおり表示します（T-7 決定済み）。原因（特定の枠に入れる人の不足など）の分析・表示は行わず、不成立の事実と、その日に勤務できる人数だけを示します（T-3 決定済み）。

不成立の判定は、ハード制約を満たす案が 0 件であること（5.4 節の最初の状態が「不可」であること）で行います。枠ごとの可能人数を独立に数える方法は、1 人が複数の枠に入れる場合があるため誤判定します。

## 7. 出力仕様

### 7.1 月間の表示

月間の結果は、次の 3 つの表示（タブ）で表します。枠の番号・名称は画面に表示せず、勤務時間で表します。営業日数・成立した日数・不成立の日数を、タブの上に表示します。

| 表示 | 内容 |
| ---- | ---- |
| カレンダー表示 | 営業日を、月〜金の週ごとのカレンダーで表示します。各日に、勤務時間ごとに氏名をまとめて表示します（例：`7:30–14:30 山田・佐藤`）。不成立の日は赤で「不成立（勤務可 n 名）」と表示します。祝日は祝日名を表示し、選択できません。日付を押すと日別詳細を開きます |
| 従業員別表示 | 行に従業員、列に営業日を並べます。各セルに、割り当てた勤務時間（例：`7:30–14:30`）を表示します。「休」は休み、「–」は割り当てなし、「×」は不成立の日です。右端に各人の出勤日数を表示します。従業員名の列は固定します |
| 日別詳細 | 日付を選び、その日の結果を 7.2 節の表と時間軸バーで表示します。不成立の日は、不成立である旨と勤務できる人数を表示します |

カレンダー表示と従業員別表示の時刻は、前 0 なしの `7:30–14:30` 形式とします。日別詳細の時刻は、7.2 節のとおり 24 時間表記・前 0 埋めの `07:30〜14:30` 形式とします。

### 7.2 1 日分の結果（日別詳細）

以降の表は、営業日 1 日分の結果です。

| 項目     | 内容                             |
| -------- | -------------------------------- |
| 割り当て | 枠 1〜6 ごとに、割り当てられた氏名・雇用区分・勤務時間（例：`07:30〜14:30`）・休憩時刻（例：`12:00〜12:45`） |
| 希望時間帯 | 割り当てられた各人が入力した時間帯（例：`07:30〜18:30`） |
| 選定根拠（ログ） | 画面には表示せず、営業日ごとに日付を添えて INFO ログに出力する（氏名に含まれる改行などの制御文字は、偽のログ行を防ぐため `\n` の形式に変換して出力する）。割り当てた各人の希望時間帯・割り当てた枠・差（分。5.2 節の「入力した時間帯の長さ − 割り当てた枠の勤務時間」）・入れる枠（H-3 を満たす枠すべて）、未出勤者の理由と入れる枠、ずれの合計（`合計 = 90 + 30 + … = 240 分`） |
| 未出勤者 | 割り当てられなかった従業員と「休み」の従業員の一覧（勤務なし。氏名に雇用区分を添えます）。理由を「休み」「入れる枠はあったが、より小さいずれの案が選ばれた」「入れる枠はあったが、同じずれの案があり、入力順で優先度が高い <氏名> が選ばれた」「どの枠にも入れない」のいずれかで示す |

成立時はこれらの項目を表形式で表示します。割当結果の表の列は「氏名・区分・勤務時間・休憩時間・希望時間帯」の順とし、勤務時間と休憩時間は 24 時間表記・前 0 埋め（`07:30〜14:30`、`12:00〜12:45`）で各行に表示します。それぞれの右に、範囲の長さを `(hh:mm)` 形式の合計時間として添えます（例：`07:30〜14:30 (07:00)`、`12:00〜12:45 (00:45)`）。合計時間はサーバーでは算出せず、画面側の JavaScript で算出します。行は枠 1 → 6 の順に並べ、枠の名称は画面に表示しません。

「選定根拠」（差・入れる枠・ずれの合計）は画面に表示せず、ログで後から追えるようにします。入れる枠のうち割り当てた枠を並べて記録することで、他の枠にも入れたが、全体のずれ（スコア）が最小となるためその枠が選ばれたことを確認できます。案の総数と同点の件数は記録しません。

入れる枠があるのに割り当てられなかった人のうち、割り当て済みの人と同じ枠で入れ替えてもずれの合計（スコア）が変わらない人は、同点の案があり 5.3 節の規則で入れ替え前の案が選ばれたものとして、優先された人（割り当て済みの人のうち、枠 1 → 6 の順で最初にその条件を満たす人）の氏名を示します。どの人と入れ替えてもずれの合計が変わる場合は、より小さいずれの案が選ばれたものとして示します。2 人以上の入れ替えを伴う同点は、氏名の判定の対象外とし、後者の文言になる場合があります。

また、表に加えて、7:30〜18:30 の時間軸バーで各人の勤務時間と休憩時間を併記します（Issue #18 で T-2 の決定を見直し）。バーには勤務と休憩を区別する色分けの凡例（「勤務」「休憩」）を表示します。早番・遅番の区別は廃止したため、凡例にも表示しません。

## 8. 画面仕様

画面は「1 対象月と従業員」「2 日ごとの希望」「3 結果」の 3 画面のステップ形式です。入力から結果表示までは 1 つのフォーム・1 リクエスト（`POST /shift`）で完結し、画面 2 で「1 か月分のシフトを作成」を押したときに送信します。画面の切り替えは JavaScript で行い、切り替えだけではサーバーに送信しません。

- 各画面は 1 画面に収め、ページ全体は縦にスクロールさせません。内容が長い部分（従業員一覧・カレンダー・入力パネル・結果）だけを、枠の中でスクロールします
- 上部にステップ表示を置き、押すと画面を移動できます。下部に「戻る」「次へ」ボタンを置きます（画面 2 の「次へ」は「1 か月分のシフトを作成」、画面 3 は「戻る」のみ）
- 入力チェックのエラー（V-2〜V-9）は、サーバーから戻ったときに画面 1 の上部へまとめて表示します。該当する従業員の行、曜日、または日付を示します

### 8.1 画面 1：対象月と従業員

- 上部に対象月の切り替え（「◀」「▶」）と、営業日数・祝日数を表示します（F-9）。既定の対象月は、保存済みの最後の対象月です。保存済みがなければ、画面を開いた日の月とします
- 左に従業員の一覧を置きます。列は「並べ替え・従業員名・区分・基本シフト（要約）・削除」です。最初の列に各行の「▲」「▼」ボタンを、最後の列に「削除」ボタンを置きます。区分のプルダウンは「常勤」「パート」「管理職」で、追加した行を含め初期値は「常勤」です。基本シフトの要約は、`07:30〜18:30` の形式（曜日ごとに違うときは、最も早い開始〜最も遅い終了）で表示します
- 一覧の行を選ぶと、右に、選んだ従業員の曜日ごとの基本シフトを表示します。列は「曜日（月〜金）・開始・終了」で、各曜日に「全曜日へ」ボタンを置き、その曜日の設定を全曜日にコピーできます。開始・終了は 30 分単位のプルダウンです。この画面では「休み」は入力できません。休み希望は画面 2 の個別変更で入力します
- 一覧の下に「行を追加」ボタンを置きます。入力表が 12 行のときは無効にします

画面を最初に開いたときは、従業員の上限（12 名）に合わせて、入力行を 12 行用意します。保存済みの従業員の入力があるときは、それを入力順に先頭の行へ復元し、残りを空の行にします（F-7）。基本シフトが「休み」で保存されている曜日（この仕様変更前に保存されたもの）は、既定の 7:30〜18:30 として復元します。保存済みの入力がなければ、すべて空の行です。画面を開いたときに復元するのは従業員の入力と日ごとの個別変更で、決定したシフトは画面 3 で表示します（8.3 節）。

### 8.2 画面 2：日ごとの希望

- 左に、対象月の営業日を月〜金の週ごとに並べたカレンダーを置きます。祝日は祝日名を表示し、選択できません。個別変更がある日は色を変え、「変更 n 名」と表示します
- 日付を選ぶと、右に、その日の従業員ごとの「休み・開始・終了」を表示します。初期値はその曜日の基本シフトです。基本シフトと同じ内容にすると、その従業員の変更は消えます。「この日を基本に戻す」ボタンで、その日の変更をすべて消します
- 従業員の追加・削除・並べ替え、対象月の変更をしても、日ごとの個別変更は破棄しません。個別変更は従業員名と日付で持つためです。従業員の氏名を変えると、その従業員の個別変更は無視されます（4.2 節）

### 8.3 画面 3：結果

7.1 節の 3 つの表示を、タブで切り替えます。カレンダー表示の日付を押すと、その日の日別詳細を開きます。

「1 か月分のシフトを作成」で算出した直後は、今回の結果を表示します。それ以外（画面を開いた直後や、画面 1 で対象月を切り替えたあとに画面 3 を開いたとき）は、その対象月の保存済みのシフト（8.4 節）を表示し、「保存済みのシフトを表示しています」と示します。保存済みのシフトがない月は、「この月のシフトはまだ作成されていません」と表示します。

保存済みのシフトは、作成した時点の内容をそのまま表示します。その後に従業員の氏名・区分・基本シフト・個別変更を変えても、「1 か月分のシフトを作成」を押して保存し直すまで、表示は変わりません。配布済みのシフトを、そのまま見返せるようにするためです。

### 8.4 保存

保存（F-7）は、入力チェック（V-1〜V-9）を通って算出まで完了したときに行います。不成立の日があっても、算出まで完了していれば保存します。保存する内容は次のとおりです（T-10 決定済み）。

- 保存の対象は、対象月を含む年（暦年）の分だけです。別の年を対象に保存したときは、以前の年のデータをすべて削除します
- 従業員の入力（並び順・氏名・区分・曜日ごとの基本シフト）は 1 組だけ持ち、最新の内容で上書きします
- 日ごとの個別変更は、日付と従業員名ごとに、最新の内容で上書きします。送信するのは対象月の分です。他の月の保存済みの個別変更は、そのまま残します
- 決定したシフトは、対象月の分を今回の結果で置き換えます。他の月の保存済みのシフトは、そのまま残します。営業日ごとに、次の内容を、作成した時点のまま保存します（従業員の氏名・区分は、その時点の値を写して保存します。あとで従業員を変更・削除しても、保存済みのシフトは変わりません）
  - 成立した日：割り当てた各人の氏名・区分・勤務時間・休憩時刻・希望時間帯と、未出勤者の一覧（理由を含む）
  - 不成立の日：不成立であることと、その日に勤務できた人数

入力エラーのときは保存しません。既存の保存内容は、エラーにせず最新の内容で上書きします。同じ月を作り直したときも、置き換えの確認は表示せず、そのまま上書きします（管理者は 1 人で、押し間違いの影響を許容するため）。保存に失敗した場合は、算出結果は通常どおり表示したうえで、エラーと「もう一度シフトを作成して保存し直してください」というリトライを促す文言を表示します。

### 8.5 フォームのバインディング

入力行は JavaScript で動的に追加します。Spring MVC でリスト形式のフォームを受け取るため、`name` 属性には連番のインデックスを付与します。曜日のインデックスは 0（月）〜4（金）です。

```html
<input name="targetMonth" value="2026-10" /> <!-- 対象月 -->
<input name="employees[0].name" />
<select name="employees[0].employmentType"> ... </select> <!-- 雇用区分 -->
<select name="employees[0].days[0].start"> ... </select> <!-- 基本シフト：月曜の開始 -->
<select name="employees[0].days[0].end"> ... </select> <!-- 基本シフト：月曜の終了 -->
<input name="adjustments[0].date" value="2026-10-20" /> <!-- 個別変更：日付 -->
<input name="adjustments[0].employeeName" /> <!-- 個別変更：従業員名 -->
<input name="adjustments[0].off" type="checkbox" /> <!-- 個別変更：休み -->
<select name="adjustments[0].start"> ... </select> <!-- 個別変更：開始 -->
<select name="adjustments[0].end"> ... </select> <!-- 個別変更：終了 -->
```

**インデックスに欠番があると正しくバインドできません。** 行の削除機能を実装する場合は、削除後に必ずインデックスを振り直してください。

行の削除（F-6）は、各入力行の「削除」ボタンで行います。入力表が 1 行のときは、その行の削除ボタンを無効にし、最低 1 行を残します。削除後は `name` 属性のインデックスを 0 から連番に振り直します。

行の並べ替え（F-8）は、各入力行の「▲」（上へ）「▼」（下へ）ボタンで行います。先頭行の「▲」と末尾行の「▼」は無効にします。氏名・区分・曜日ごとの基本シフトの入力値は行と一緒に移動し、移動後は `name` 属性のインデックスを 0 から連番に振り直します。入力順は同点時の優先順位（5.3 節）に使われるため、並べ替えは同点のときに採用される案に影響します。

## 9. 非機能要件・技術構成

| 項目       | 内容                                                                    |
| ---------- | ----------------------------------------------------------------------- |
| 状態管理   | セッションやアプリケーションスコープには状態を保持しません。入力・計算・出力が 1 リクエストで完結します |
| データ保存 | 従業員の入力・日ごとの個別変更・決定したシフトを、H2（ファイルモード）へ対象年（暦年）の分だけ保存します（F-7、8.4 節）。過去の年の履歴は持たず、再起動後も残ります |
| 祝日データ | 内閣府の「国民の祝日」CSV を取得して H2 に保存します（4.1 節、F-10）。利用者の入力ではない参照データのため、8.4 節の保存の対象外です。取得には JDK 標準の HTTP クライアントを使い、新しいライブラリは追加しません |
| 性能       | 従業員 12 名までを想定します（T-6 決定済み）。1 日の算出は数ミリ秒で、営業日は最大 23 日程度のため、1 か月分でも 1 秒以内を想定します |
| 認証・同時利用 | 認証は実装せず、同時利用も想定しません。ただし保存データの改ざんを防ぐため、`POST /shift` は同一オリジンからのリクエストだけを受け付けます（`Sec-Fetch-Site` または `Origin` を検証し、別オリジンは 403） |
| 技術       | Java 25 / Spring Boot 4.1.1 / Thymeleaf + 素の JavaScript / Maven       |

保存には `spring-boot-starter-data-jdbc` と H2 を使用します。JPA（`spring-boot-starter-data-jpa`）は使用しません。
