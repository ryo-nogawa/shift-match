# 要求定義

## 1. 本書の目的

Shift Match を開発する理由、解決すべき課題、対象範囲を定義します。実現手段は [要件定義](specifications.md) に記載します。

機能の追加・変更を検討する際は、本書に立ち返り、目的に沿うかを判断してください。

## 2. 背景と課題

シフトは管理者が手作業で作成しています。従業員の希望は日ごとに変わるため、管理者は毎日希望を集約し、営業時間と人員配置のルールを満たす組み合わせを自力で探しています。1 か月分を作る場合は、これを営業日の数だけ繰り返す必要があり、負担がさらに大きくなります。

| 課題             | 内容                                                             |
| ---------------- | ---------------------------------------------------------------- |
| 作成の負担       | 日ごとに組み合わせを手作業で探す必要があり、時間を要します       |
| 希望の反映漏れ   | 全パターンを検討できず、より希望に沿う組み合わせを見落とします   |
| ルール違反の混入 | 人員配置ルールを満たしているかの確認を目視に頼っています         |
| 属人化           | 作成手順が管理者の経験に依存しています                           |

## 3. 目的

従業員の希望をもとに、業務ルールを満たす組み合わせを自動で提案し、上記の課題を解消します。

- 管理者が組み合わせを探す作業から解放されている
- ルール違反のシフトが作成され得ない
- 希望をより多く反映した組み合わせが選ばれている

## 4. 利用者

- **管理者**：希望を入力し、シフト案を得ます。本アプリケーションの唯一の操作者です
- **従業員**：希望を管理者に提出します。本アプリケーションを直接操作しません

## 5. 業務上の制約条件

業務側の前提であり、開発の都合で変更できません。

| No  | 制約         | 内容                                        |
| --- | ------------ | ------------------------------------------- |
| C-1 | 営業時間     | 7:30 〜 18:30                               |
| C-2 | 勤務時間     | 出勤時刻と退勤時刻は枠ごとに定めます。早く出勤した人から順に退勤します |
| C-3 | 人員配置     | 時間帯ごとの勤務中人数（休憩中の人を含みます）は [要件定義 2 章](specifications.md) の表のとおりです（7:30 は 2 人、9:00〜14:30 は 8 人など）。休憩中の人を除いても、常に 2 人以上が勤務している必要があります |
| C-4 | 希望の変動   | 従業員の希望は、曜日ごとの基本の勤務パターンがあり、そのうえで日ごとに変わることもあります |
| C-5 | 勤務の連続性 | 勤務時間は分割せず、連続した時間とします    |
| C-6 | 休憩         | 労働基準法第 34 条に従い、勤務時間が 6 時間を超え 8 時間以下なら 45 分以上、8 時間を超えるなら 60 分以上の休憩を与えます |
| C-7 | 従業員数     | 12 名を上限とします                         |
| C-8 | 営業日       | 月曜日から金曜日です。土曜日・日曜日と日本の祝日は営業しません。祝日は内閣府の「国民の祝日」CSV を正規データとします |

## 6. スコープ

### 対象

- 1 か月分のシフト作成（営業日ごとに 1 日分の案を作成します）
- 従業員の希望に基づく組み合わせの提案
- 従業員 12 名のうち 8 名を枠へ割り当てること。従業員ごとの雇用区分（常勤・パート・管理職）を入力・保存・表示しますが、割り当てでは区分を考慮しません（区分ごとの扱い、パートの計算方法は別の仕様変更で対応します）
- 従業員の入力（曜日ごとの基本シフトを含む）、日ごとの個別変更と決定したシフトを、対象年（暦年）の分だけ保存し、次回以降の入力に復元し、決定したシフトを画面で見返せること（毎回の入力の手間を減らし、配布済みのシフトをそのまま確認するため。別の年を保存したときは、以前の年のデータを残しません）

### 対象外

| 項目                             | 除外の理由                                         |
| -------------------------------- | -------------------------------------------------- |
| 認証・ユーザー管理               | 操作者は管理者のみであり、必要としません           |
| 履歴の保存                       | 保存するのは対象年の分のみです。過去の年の蓄積・参照は必要としません |
| 週次のシフト作成                 | 営業日ごとの割り当てと月単位の作成で目的を達成できます |
| 給与計算・勤怠実績の管理         | 本アプリケーションの目的に含まれません             |
| 出勤回数の公平化                 | 日をまたぐ過去実績の考慮が必要となり、今回のスコープを超えます。営業日ごとに独立して最適化します |

## 7. 成功基準

| No  | 基準                                                                 |
| --- | -------------------------------------------------------------------- |
| S-1 | 業務ルールに違反したシフトが出力されないこと                         |
| S-2 | 希望を反映した組み合わせが、手作業より短時間で得られること           |
| S-3 | 条件を満たす組み合わせが存在しない場合、その事実（どの日が不成立か）が管理者に伝わること |
| S-4 | 1 か月分のシフトが、一度の操作で得られること。土日と日本の祝日には割り当てないこと |

## 8. 用語

| 用語       | 定義                                                                 |
| ---------- | -------------------------------------------------------------------- |
| 時間帯     | 勤務中人数（休憩中を含む）が一定の区間。開始時刻を含み、終了時刻を含みません           |
| 希望       | 従業員が提出する、勤務できる時間帯（開始・終了）または休みの申告です |
| 営業日     | 月曜日から金曜日のうち、日本の祝日でない日です |
| 基本シフト | 従業員ごとに曜日（月〜金）ごとに設定する、勤務できる時間帯です（休みは設定しません。休みは個別変更で申告します） |
| 個別変更   | 特定の営業日・特定の従業員について、基本シフトと異なる希望（休みまたは時間帯）を設定することです |
| 対象月     | シフトを作成する年月です。保存の対象は、対象月を含む年（暦年）です |
| 枠         | システムが割り当てる勤務時間の単位（出勤時刻と退勤時刻の組）です     |
| 雇用区分   | 従業員の区分です。「常勤」「パート」「管理職（社長・部長などの役職者）」の 3 択です |
