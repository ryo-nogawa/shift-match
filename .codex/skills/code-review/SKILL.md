# コードレビュー

このリポジトリのルートで実行する。通常は `$code-review <比較元ブランチ>` の形で呼び出し、指定されたローカルブランチの先端と現在の作業ツリーを比較する。コミット済みの差分に加え、ステージ済み・未ステージの変更と新規ファイルも対象に含める。比較先や対象ファイルも指定された場合は、その指定を優先する。

## 実行モード

トークン消費を抑えるため、次のオプションを受け付ける。指定がなければ通常（全観点・全差分）で実行する。

- `再レビュー <前回レビューしたコミット>`：比較範囲を「前回のコミット〜現在」に絞り、前回の MUST 指摘の解消確認を主目的にする。両サブエージェントへ、その範囲外を読まないよう指示する。
- `観点 quality` / `観点 security`：指定した観点のサブエージェントだけを起動する。省略時は両方を起動する。起動しなかった観点のレポートは今回の結果として扱わず、その旨を回答に明記する。

比較元ブランチが省略された場合は `main` を使い、その旨を結果に明記する。比較元が見つからない場合は、別のブランチを推測せず、レビューを開始しないでユーザーに指定を求める。

1. 比較元ブランチが存在することを確認する。両サブエージェントへ同じ比較範囲を明示する。
2. `code_quality_review` と `security_risk_review` の2つのサブエージェント（`観点` 指定時は該当する方だけ）を起動する。ビルド・テストはサブエージェントに実行させず、実行済みの結果は `target/surefire-reports/` を読むよう指示する。前者には `.agents/agents/code-quality-review.md`、後者には `.agents/agents/security-risk-review.md` に従うよう指示する。双方ともレビュー対象のコードや設定は変更しない。
3. 各サブエージェントの完了後、数字だけの最終返答に依存せず、`target/reviews/code-quality-review.md` と `target/reviews/security-risk-review.md` を読む。各レポートが今回の比較範囲を示し、今回の実行で保存されたことを確認する。ファイルがない、古い、比較範囲が違う、または最終返答の件数と内容が一致しない場合は、該当レビューを完了と扱わず、原因を確認する。
4. `.agents/review-template.md` に従い、各レポートの実際の MUST 行を数える。「該当なし」は数えない。指摘の根拠・発生条件・影響・改修方針を確認し、必要なら修正要否を判断する。レビュー中に修正まで依頼されていない場合、レビュー対象のコードは変更しない。
5. ユーザーへの回答は日本語で、比較範囲、**コード品質の MUST 件数と各指摘の概要**、**セキュリティーの MUST 件数と各指摘の概要**を分けて示す。各概要には対象箇所、問題と影響、改修方針を簡潔に含める。0 件なら「0 件（該当なし）」とする。詳細レポートへのリンクと、実行した確認コマンドおよびその結果も記載する。レビューが完了しなかった場合は、確認できた範囲と理由を正確に伝える。
